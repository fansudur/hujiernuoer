# Interactive geodata v1
- `terrain_local.json` and `terrain_context.json`: width, height, bounds=[west,south,east,north] (WGS84 **pixel outer edges**), elevations flat numeric meters row-major north→south. Vertices at pixel centers: lon=w+(col+.5)/width*(e-w), lat=n-(row+.5)/height*(n-s). Metadata crs EPSG:4326, vertical_datum EGM2008, source. No vertical exaggeration baked in. UI default exaggeration=1; any slider must say ×N. This is historical DSM, NOT bathymetry/current water level. Local and context have independent grid sizes.
- `boundary.geojson`: user-drawn study polygon WGS84; not cadastral boundary.
- `water_samples.geojson`: FeatureCollection polygon/multipolygon features each with properties.date YYYY-MM, class_code 2, quality_qualified boolean, detected_water_ha. Real JRC classified cell boundaries clipped to study polygon; NOT area-proportional invented shapes. Select features with exact date only. No morph/interpolation/no water-height animation; dates without geometry must show unavailable, not dry.
- `monthly.json`: object records[] with date YYYY-MM, year, month, temperature_C, precipitation_mm, wind10_m_s, radiation_MJ_m2_day, dtr_C, snow_water_mean_mm, snowfall_water_mm, lake_area_ha (dual95-qualified only; null otherwise), lake_detected_area_ha (raw), lake_qualified boolean (dual95 all months), lake_status, lake_valid_pct, lake_outer_valid_pct, has_water_geometry boolean, completeness object of original completeness flags, ndvi_windows array of actual seasonal records containing time_window_id,start_UTC,end_UTC,spatial_unit_id,quality_accepted,ndvi. NDVI is seasonal, never monthly or forward-filled. Null means missing, never zero. metadata field dictionary and coverage accompany records.
- `buildings.geojson`: only source-verifiable footprints; absent building data never replaced with invented locations/heights.

## Important zero / absence distinction
`has_water_geometry` means raster sample AVAILABLE, including verified sample months with zero detected water (2006-08, 2007-07, 2011-08). Consult `water_sample_index.json`: listed date + feature_count=0 = observed zero detected open water, NOT unavailable; unlisted date = no geometry sample. Neither means lake dry. Monthly quality null remains missing. Water polygon clipping creates negligible boundary-cell area differences from frozen pixel-center area totals; use frozen area field for charts, never infer area from polygons.

## OSM buildings

Partial town context only, not exhaustive inventory. All height_m=null; show 2D footprints only. Render attribution © OpenStreetMap contributors with https://www.openstreetmap.org/copyright . ODbL 1.0. Raw XML is audit-only, do NOT deploy raw contributor account metadata.

`water_nodata.geojson`: exact class-0 cell polygons clipped to study boundary, properties.date. Overlay hatched/gray for sample dates. Legend must distinguish blue=class2 detected water; remaining observed study area=class1 not detected open water (NOT proven dry); gray=class0 unavailable. For non-sample dates the entire water overlay unavailable. `classification_caution` on sample/index marks 2010 historical product classification dispute; 2008 monthly values are retained in frozen main analysis; no 2008 geometry is selected in this small display-sample set (not a quality exclusion). Default 2024-08 and recommended tour 2001-07,2014-08,2018-08,2021-08,2024-08 avoid disputed years.
